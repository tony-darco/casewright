test("applies SAVE10 to a $40 cart", async () => {
  const cart = await newCart();
  await cart.add(item({ price: 40 }));
  await cart.apply("SAVE10");

  expect(cart.discount).toBe(-4.00);
  expect(cart.total).toBe(36.00);
});

How it works

A retrieval pipeline that reads before it writes.

Casewright doesn't guess at your code. It decomposes each specification, retrieves the exact context every case needs, and only then generates the test — so the output reflects how your system actually behaves.

STEP 01Decompose

A specification rarely maps to a single test. Casewright breaks each one into simple, comprehensive cases — the happy path, the boundaries, and the failure modes — so nothing quietly goes uncovered.

in: specificationout: case list
STEP 02Retrieve

For every case, a hybrid agentic RAG step gathers the exact code, types, and fixtures it needs. This retrieval pipeline is the core of the system — it's what keeps generated tests grounded in your real interfaces instead of plausible-looking fiction.

per case→ grounded context
STEP 03Generate

From that grounded context, Casewright writes accurate unit, integration, and end-to-end tests in the frameworks you already use — ready for a human to review and drop into the suite.

out: unitintegratione2e
Hybrid agentic RAG

Why retrieval, not just a prompt

A model asked to "write a test" with no context invents interfaces, guesses payloads, and asserts against behavior that doesn't exist. The tests look right and fail on contact.

Casewright inverts that. Each case drives an agentic retrieval loop that pulls the relevant source, type definitions, existing fixtures, and prior tests — combining semantic and keyword search — then generates against what it found. Grounded in, grounded out.

spec └─ decompose ├─ case: happy path ├─ case: edge / boundary └─ case: failure mode │ ▼ retrieve (hybrid: semantic + keyword) ├─ source under test ├─ types & interfaces ├─ fixtures / factories └─ neighboring tests │ ▼ generate → unit · integration · e2e

Safety by default

Generated code is untrusted — we treat it that way

Test code generated from specifications can be shaped by untrusted text pulled from a retrieved corpus. Casewright never runs it for you behind the scenes: every generated test is meant for human review and executes in a sandbox, never straight into a developer machine or CI pipeline.
